# ADR 0001 — Why NIAH passes while the multi-hop task fails

- **Status:** accepted
- **Date:** 2026-08-25
- **Scope:** how this repo measures effective context, and what it refuses to conclude
- **Outcome:** the gap is real and disjoint, but it is a task-difficulty floor
  rather than a context effect. See the postscript.
- **Numbers:** all from `results/effective-context.md`, generated by
  `scripts/generate_results.py` from `results/eval-cache.json`.
  None are typed by hand into this document.

## Context

"Effective context" is the length at which a model still does useful work,
as opposed to the advertised length in `config.max_position_embeddings`.
Everyone agrees the two differ. Almost nobody agrees on how to measure the
first, and the default instrument — needle-in-a-haystack — is the reason.

NIAH became standard because it produces a legible artifact: a depth-by-length
grid, green where the model found the needle. It is cheap, it needs no
labelled data, and the score is unambiguous. It is also, structurally, the
easiest thing you can ask a transformer to do with a long context.

The decision recorded here is what to do about that.

## The problem with the instrument

NIAH is single-hop lexical retrieval. The question names Zurich; exactly one
line in 8,000 tokens says Zurich; the model copies the number after it. That
is the induction-head primitive — match a token, emit what followed it last
time — which is present in small models very early in training and is close
to the most robust circuit a transformer has.

So a passing NIAH score establishes one thing: **the positional encoding still
resolves at that length.** Attention can still address a token 8,000 positions
back and copy from it. That is genuinely worth knowing. It is not the same
claim as "the model can use 8,000 tokens of context", and the two get
conflated constantly, because NIAH is reported as though it were the second.

The gap is not a subtlety. Retrieving a fact and *composing* two facts are
different circuits with different failure curves:

- **Single-hop degrades gracefully.** The needle stays lexically unique. As
  positional fidelity erodes, attention gets fuzzier about *where* the match
  is, but the match is still the only candidate, so the copy still lands.
- **Two-hop degrades sharply.** Hop one produces an entity that hop two must
  use as a query. If hop one drifts to a distractor, hop two retrieves that
  distractor's number — confidently, and completely wrong. Errors compose
  rather than average, so the curve has a cliff rather than a slope.

Two circuits with different failure curves cannot be summarised by one number,
and NIAH reports the number belonging to the more robust one.

## Decision

**Measure both tasks on the same haystack, and report effective context per
task rather than as a single figure for the model.**

Concretely:

1. `multihop.py` is built as the *minimal* strengthening of `niah.py`. Same
   filler corpus, same document delimiters, same answer format ("answer with
   the number only"), same lengths, and — deliberately — the **same scoring
   function**, a four-digit exact match on a word boundary. One hop is the
   only difference.
2. The pass bar (50%) is fixed in the script before any run, not chosen
   after seeing the curves.
3. `scripts/generate_results.py` asserts that NIAH scores at least as high as
   multi-hop at every length, and exits non-zero if that ever breaks.

The control in (1) is the load-bearing part. A gap between two benchmarks
written by different people at different times explains nothing — it could be
prompt format, answer parsing, or grader leniency. Holding all of those fixed
means the separation is attributable to the hop, and the hop is the thing the
repo is about.

Choice (3) deserves a note. It commits an *ordering*, not an accuracy.
Accuracies are portable here because decoding is greedy over seeded prompts,
but the ordering is portable for a stronger reason: it would survive a
different model, a different sample size, and a different pass bar. That is
the kind of claim worth putting behind an assertion.

## Consequences

**What this buys.** A model can now be described honestly: NIAH-effective
context and composition-effective context are separate numbers, and the
advertised figure is an upper bound on both. When they diverge, the divergence
itself is the reportable finding — it says the positional encoding is fine and
the *use* of the retrieved content is what broke, which points at a different
fix than "extend the context window".

**What it costs.** Two evaluations instead of one, and a task that needs
hand-designed distractors. Distractors are not decoration: without complete
competing coordinator+badge chains, only one badge number exists in the
document and "the badge number" is answerable without hop one at all. The task
silently degenerates back into NIAH. `tests/test_tasks.py` asserts the chains
are complete and that the answer badge is unique among all badges, because
both failures would inflate the multi-hop score and shrink the gap — that is,
they would bias *against* this repo's own headline, which is exactly the
direction a test should be watching.

**What it does not establish.** Three things, stated plainly:

- **Capability is confounded with context.** Qwen2.5-0.5B-Instruct is a weak
  two-hop reasoner at *any* length. Some of the multi-hop deficit at 1k is
  simply the model being small, not the context being long. The defensible
  claim is the *trend* across lengths and the *ordering* against NIAH, not the
  absolute multi-hop accuracy. Separating capability from context needs the
  same sweep on a larger model, which CPU-only inference does not permit.
  **This turned out to be the binding limitation — see the postscript.**
- **The sweep stops well short of the advertised window.** Against 32,768
  advertised. Nothing in the results file is extrapolated above the longest
  length actually run, and "NIAH passes at the top of the sweep" must not be
  read as "NIAH passes at 32k". `results/effective-context.md` names the
  lengths that ran.
- **The scaling analysis and the evaluation are not connected.** `scaling.py`
  establishes closed-form properties of PI, NTK and YaRN. The evaluation runs
  the model at its native RoPE settings. This repo does **not** show that YaRN
  beats PI on the multi-hop task — that requires fine-tuning under each
  scaling method, and there is no fine-tuning budget here. The two halves
  answer the same question from different directions; they are not one
  experiment.

## Alternatives considered

**Report perplexity at length instead.** Perplexity keeps falling on long
documents well past the point where retrieval fails, because most tokens are
predictable from local context alone. It is the least sensitive instrument
available for this question.

**Use an existing long-context benchmark (RULER, LongBench, ∞Bench).** Better
instruments than what is here, and the right choice for a real evaluation.
Rejected for this repo because they bring their own prompt formats and graders,
which reintroduces exactly the confound the shared scorer was built to remove.
The point was a controlled A/B, not a leaderboard number.

**Report one "effective context" figure for the model.** This is the status
quo and it is what the repo argues against. A single figure has to pick a
task, and picking NIAH is what produces the overstatement.

**More hops.** Three-hop widens the gap and makes a better headline. Rejected:
the 0.5B model already collapses at two, so a third hop would measure the
floor, and every extra hop adds a way for the task to be unfair that is
harder to argue is *only* about context.

## Postscript — what the measurement actually showed (2026-08-25)

Everything above was written before the sweep ran. The sweep changed the
claim, and the original text is left intact so the change is visible.

**The gap is real and larger than expected: NIAH 100% against multi-hop 17%
at 1,024 tokens, with disjoint confidence intervals.** But the separation is
already fully present at the *shortest* length measured, and 1,024 tokens
cannot be where a 32,768-token model runs out of positional resolution. So
the gap is mostly a **task-difficulty floor**, not a context effect.

The `bridge_found` diagnostic makes the mechanism concrete and argues against
a positional explanation. The model names the intermediate entity *less* often
than it produces the correct final answer. It is not retrieving the
coordinator and then failing to carry it forward — it is mostly not attempting
hop one at all, and emitting a plausible badge number from somewhere in the
document. That is a capability failure, and it would look the same at 512
tokens.

This forces the headline down to something narrower and more defensible:

> A passing NIAH score licenses no conclusion about composition. The two
> instruments measure different things, and the difference is large enough to
> separate with 12 samples per cell.

What the sweep does **not** support, and what the title of this ADR would
have implied on its own: that this model's positional encoding degrades
somewhere between 1k and 8k. To measure *that*, the harder task has to be one
the model can actually do at short context, so that the length where it stops
doing it is a measurable boundary rather than a floor it started on. A 0.5B
checkpoint does not clear that bar, and sweeping further would not change it.

**Was the task design wrong, then?** No — and this is worth being precise
about, because the temptation is to weaken the task until a length effect
appears. Two hops with distractors is the minimal strengthening of NIAH, and
weakening it to manufacture a gradient would produce a curve that says more
about the tuning than the model. The right fix is a larger model, not an
easier task. The wrong fix would have been to report the observed gap as a
context effect because that is the more quotable finding.

`scripts/generate_results.py` derives which of the two explanations the data
supports and writes the corresponding paragraph, so this distinction cannot
drift out of the results file if the sweep is re-run on a stronger model.
