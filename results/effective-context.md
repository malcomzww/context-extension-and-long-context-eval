- RoPE base: 1000000

`run_eval.py` gets the same scores. Latency is not.

## The finding

**At 1,024 tokens NIAH scores 100% and the two-hop
task scores 17%.** The confidence intervals do not
overlap: NIAH's lower bound is 76% and multi-hop's upper
bound is 45%. One hop is the only difference between the
two prompts -- same filler, same length, same answer format, same
scorer -- so the separation is attributable to composition, not to
task presentation.

This is the sense in which NIAH overstates effective context: reading
the NIAH row alone, this model looks fine at 1,024 tokens, and it
is not fine at that length for any task that has to use two facts
together -- which describes most real long-context work: reconciling a
figure against its footnote, following a reference into another
section, answering anything a summary does not already state.

What that does **not** yet say is *why*. Two explanations predict the
same table -- positional information degrading with length, or the task
simply being beyond this model at any length -- and they license very
different conclusions. The next section separates them from the data.

### Is this a context effect or a task-difficulty floor?

**A floor, mostly.** At the shortest length measured (1,024 tokens) multi-hop already scores 17% -- below the 50% bar -- while
NIAH scores 100%. At 1,024 tokens
context length is not plausibly the binding constraint, so most of
the deficit is this model being unable to compose two facts *at any
length*, not positional information degrading.

That makes the honest claim narrower than the headline usually is.
What this sweep establishes is that **NIAH and two-hop retrieval
measure different things, and a passing NIAH score does not license
any claim about composition** -- not that this model's positional
encoding fails somewhere between the two. Distinguishing those needs
a model that clears the two-hop bar at short context, so that the
length at which it stops clearing it is measurable. A 0.5B
checkpoint does not, and no amount of sweeping fixes that.

### Direction of the gap

At every length in the sweep, NIAH scores at least as high as multi-hop:

- 1,024 tokens: NIAH 100% vs multi-hop 17% (+83 pp)
- 2,048 tokens: NIAH 100% vs multi-hop 8% (+92 pp)

The ordering is the portable claim -- it does not depend on the sample
size or on where the pass bar sits, and this script exits non-zero if any
length breaks it.

### Which hop fails

`bridge_found` records whether the model named the intermediate entity
even when it got the badge number wrong. It separates a retrieval failure
(hop one missed) from a composition failure (hop one landed, hop two did
not).

## Limits of this measurement

- One model, one size. A 24-layer 0.5B checkpoint is a
  weak two-hop reasoner at *any* length, so part of the multi-hop deficit
  is capability rather than context. The length *trend* is the claim; the
  absolute multi-hop number is not transferable to a larger model.
- 12 and 12 samples
  per cell give wide intervals. They are wide enough to support a
  disjoint-CI claim only where the gap is large.
- The sweep stops at 2,048 tokens against a 32,768-token
  advertised window. CPU prefill is the binding constraint. Nothing here
  measures the 2,048-32,768 region, and no value in this
  file is extrapolated into it.
- Synthetic filler. Real documents have topical structure a model can
  navigate; uniform filler removes that, which makes both tasks harder
  than their real-world equivalents in the same direction.
